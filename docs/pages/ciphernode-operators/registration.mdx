# Registration & Bonding

This guide walks you through the complete registration process to become an active ciphernode
operator. Make sure your node is already [running](./running) before proceeding.

> **Interactive alternative:** the dashboard can do every step on this page in your browser. It
> shows the live bond size, ticket price, and operator status, and it sends each transaction from
> the connected wallet. Open [Run a ciphernode](https://dashboard.theinterfold.com/#operator). The
> commands below remain the reference path for automated or headless setups.

## Prerequisites

Registration supports one or two wallets:

- The **operator key** runs the node and authorizes its initial bond owner.
- The **bond owner** holds FOLD and USDC and controls the position lifecycle.

Using a separate cold wallet or Safe as the bond owner is strongly recommended so the running node
does not hold the key controlling collateral. Self-ownership is supported if an operator prefers a
single-wallet setup. Ensure the selected bond-owner wallet has:

| Token                   | Amount Required                             | Purpose                      |
| ----------------------- | ------------------------------------------- | ---------------------------- |
| **FOLD**                | ≥ 100 FOLD (check `requiredCiphernodeBond`) | Ciphernode bond collateral   |
| **USDC** (or fee token) | ≥ 10 USDC per ticket (minimum 1 ticket)     | Ticket balance for sortition |
| **ETH**                 | Sufficient for gas                          | Transaction fees             |

> **Testnet tokens:** on Sepolia you can self-serve test FOLD and mock USDC from the faucet with
> `interfold faucet` (requires the `faucet` contract address in your config — see
> [Running a Node → Contract Addresses](/ciphernode-operators/running#contract-addresses)). Each
> call tops up FOLD and the fee token independently, only when your balance for that token is below
> the faucet threshold. One call dispenses enough FOLD to meet the default 100 FOLD ciphernode bond.
> If the faucet runs dry, reach out on the [community Telegram](https://t.me/enclave_e3).

## Registration Steps

### Step 1: Check Current Status

First, verify your current on-chain status:

```bash
interfold ciphernode status
```

Example output:

```
Ciphernode status on sepolia:
  Operator key: 0x70997970C51812dc3A010C7d01b50e0d17dc79C8
  Bond owner: not configured
  Registered: false
  Active: false
  Exit pending: false
  Ticket balance: 0 (0 available)
  Ciphernode bond: 0
  Pending exits: tickets=0, bond=0
  Requirements: minTickets=1, ticketPrice=10 tFOLD, ciphernodeBond=100 FOLD
```

### Step 2: Authorize the Bond Owner

From the node's operator key, authorize the wallet or Safe that will control collateral:

```bash
interfold ciphernode set-bond-owner --owner 0xBOND_OWNER
```

The owner must be nonzero and may equal the operator address, although a separate cold wallet or
Safe is recommended. The operator can correct the address before the position is funded. Once it
holds collateral or is registered, owner changes use the two-step proposal and acceptance flow
described below.

### Step 3: Fund and Register the Operator

For an EOA bond owner, run the owner-aware CLI commands using a config whose encrypted signer is
that owner:

```bash
interfold --config /path/to/owner.yaml ciphernode bond \
  --operator 0xOPERATOR bond --amount 100
interfold --config /path/to/owner.yaml ciphernode register --operator 0xOPERATOR
interfold --config /path/to/owner.yaml ciphernode tickets \
  --operator 0xOPERATOR buy --amount 100
```

The CLI submits any required token approval first. Safe owners can submit the same
`bondCiphernodeFor`, `registerOperatorFor`, and `addTicketBalanceFor` calls through the Safe
interface. The owner supplies the assets, while the operator address is added to the registry Merkle
tree and receives non-transferable tFOLD. With the recommended separate-owner setup, the hot
operator key does not control FOLD or USDC withdrawals, and protocol rewards are credited to the
bond owner.

The number of usable tickets is calculated as:

```
availableTickets = floor(ticketTokenBalance / ticketPrice)
```

With a ticket price of 10 USDC and a 100 USDC deposit, you get 10 available tickets.

### Step 4: Verify Active Status

Confirm your registration is complete:

```bash
interfold ciphernode status
```

Expected output for an active operator:

```
Ciphernode status on sepolia:
  Operator key: 0x70997970C51812dc3A010C7d01b50e0d17dc79C8
  Bond owner: 0xBOND_OWNER
  Registered: true
  Active: true
  Exit pending: false
  Ticket balance: 100 (10 available)
  Ciphernode bond: 100
  Pending exits: tickets=0, bond=0
  Requirements: minTickets=1, ticketPrice=10 tFOLD, ciphernodeBond=100 FOLD
```

## Operator CLI Commands

```bash
# Authorize the bond owner from the hot operator key
interfold ciphernode set-bond-owner --owner 0xBOND_OWNER

# Fund and register from an EOA bond-owner config
interfold --config /path/to/owner.yaml ciphernode bond \
  --operator 0xOPERATOR bond --amount 100
interfold --config /path/to/owner.yaml ciphernode register --operator 0xOPERATOR
interfold --config /path/to/owner.yaml ciphernode tickets \
  --operator 0xOPERATOR buy --amount 100

# The owner or operator can stop participation
interfold ciphernode deregister --operator 0xOPERATOR

# Check status
interfold ciphernode status --operator 0xOPERATOR
```

Omit `--operator` for a self-owned position. In the recommended two-wallet setup, run financial
commands with the bond-owner config and pass the node's operator address explicitly.

### Activation Controls

Two commands adjust the activation state of an operator without a full exit:

```bash
# Register an operator again after a full exit
interfold --config /path/to/owner.yaml ciphernode activate --operator 0xOPERATOR

# Queue collateral for exit and drop below the active thresholds
interfold --config /path/to/owner.yaml ciphernode deactivate \
  --operator 0xOPERATOR --tickets 50 --bond 25
```

`activate` sends the same registration call as `register`. Use it only to register an operator again
after a [deregister](./exits-and-slashing#step-1-deregister). The call reverts with
`AlreadyRegistered` for an operator that is still registered.

To restore the active status of a registered operator after an eligibility parameter changes
on-chain, call `refreshOperatorStatus(operator)` on the BondingRegistry. The call is permissionless.
The CLI has no command for it.

`deactivate` requires `--tickets`, `--bond`, or both. It calls `removeTicketBalanceFor` for the
ticket amount and `unbondCiphernodeFor` for the ciphernode bond amount. Both amounts enter the exit
queue and become claimable after the exit delay. The operator stays registered, so use
[deregister](./exits-and-slashing#step-1-deregister) for a full exit.

### Rotate the Bond Owner

The current owner proposes a replacement, then the new owner accepts:

```bash
interfold --config /path/to/current-owner.yaml ciphernode propose-bond-owner \
  --operator 0xOPERATOR --new-owner 0xNEW_OWNER
interfold --config /path/to/new-owner.yaml ciphernode accept-bond-owner \
  --operator 0xOPERATOR
```

Active and pending FOLD ownership accounting moves atomically on acceptance. The operator key is not
involved in rotation.

### Multi-Chain Support

Specify a chain when operating on multiple networks:

```bash
interfold ciphernode status --chain mainnet
interfold ciphernode set-bond-owner --owner 0xBOND_OWNER --chain sepolia
```

The `--chain` parameter matches the `name` field in your config's `chains` array.

## Economic Parameters

Current Sepolia defaults (verify on-chain before depositing):

| Parameter                | Value                | Description                        |
| ------------------------ | -------------------- | ---------------------------------- |
| `ticketPrice`            | 10,000,000 (10 USDC) | Cost per ticket in fee token units |
| `requiredCiphernodeBond` | 100 FOLD             | Minimum FOLD to bond               |
| `minTicketBalance`       | 1 ticket             | Minimum tickets to be active       |
| `exitDelay`              | 604,800s (7 days)    | Wait time before claiming exits    |

Query these values on-chain:

```bash
# Using cast (foundry)
cast call $BONDING "ticketPrice()" --rpc-url $RPC
cast call $BONDING "requiredCiphernodeBond()" --rpc-url $RPC
cast call $BONDING "minTicketBalance()" --rpc-url $RPC
cast call $BONDING "exitDelay()" --rpc-url $RPC
```

## Best Practices

### Maintain Buffer Amounts

- **Ciphernode bond**: Keep 10-20% above the minimum to absorb potential slashing without losing
  active status
- **Tickets**: Maintain extra tickets so you're not deactivated if one is consumed or slashed

### Monitor Your Status

Set up alerts for:

- `isActive` changing to `false`
- `SlashProposed` events targeting your address
- Low ticket balance approaching minimum

### Monitor Activation Events

Watch for `OperatorActivationChanged` events targeting your address. These fire whenever your active
status changes due to balance or bond updates.

## Troubleshooting

| Issue                     | Cause                                          | Solution                                                |
| ------------------------- | ---------------------------------------------- | ------------------------------------------------------- |
| `isActive` is false       | Below minimum ciphernode bond (80%) or tickets | Add more FOLD or tickets                                |
| Registration fails        | Already registered, banned, or unbonded        | Check `isRegistered()`, ban status, and ciphernode bond |
| Ticket purchase fails     | Insufficient stablecoin or allowance           | Ensure balance and approve spending                     |
| "NodeNotEligible" in logs | Not registered before E3 request               | Register before requests are made                       |
